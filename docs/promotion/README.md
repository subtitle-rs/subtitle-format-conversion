## 平台适配说明

### 掘金(技术深度)
- **角度**:从架构到实现,拆解 Rust+WASM+React 的工程决策
- **卖点**:纯客户端架构、subtitler 库复用、薄包装 crate、懒计算
- **目标**:吸引技术用户,为 subtitler 库导流,建立技术品牌
- **标签建议**:`Rust` `WebAssembly` `React` `前端架构` `开源项目`

### 少数派(产品评测)
- **角度**:痛点切入(装软件烦、上传怕、跨平台难),给出解决方案
- **卖点**:免费、不上传、跨平台、13 格式、4 工具
- **目标**:吸引效率工具爱好者,建立产品认知
- **配图建议**:工具截图(4 个 Tab 各一张)、格式支持列表、对比表

### V2EX(分享创造)
- **角度**:[分享创造] 节点,简洁直白,留出讨论空间
- **卖点**:纯客户端、复用 Rust 库、开源
- **目标**:技术社区传播,获取高质量反馈
- **发帖节点**:`分享创造`

### 小红书/微博(社交传播)
- **角度**:场景化痛点,emoji 密集,引导互动
- **卖点**:免费、不上传、手机能用、不用装
- **目标**:破圈到非技术用户,最大化传播
- **注意**:小红书链接可能被限流,建议引导关注/评论获取

## 发布建议

### 发布顺序(由窄到宽)

1. **先发 V2EX + 掘金**(技术社区):收集首批反馈,修正明显问题
2. **再发少数派**(产品社区):用反馈后的版本,产品视角覆盖更多用户
3. **最后发小红书/微博**(大众):配图准备好后做最大化传播

### 配图准备

- 工具首页截图(4 Tab 全景)
- 每个工具单独截图(转换/校验/规范化/信息)
- 暗色模式截图(突出设计感)
- 移动端截图(突出跨平台)
- 格式支持列表图

### 互动策略

- 每个平台都要回复评论(尤其前 24 小时)
- 收集用户反馈 → GitHub issue
- 对优质反馈公开感谢(二次传播)

## 复用素材

所有文章用到的核心数据:

- **13 种格式**:SRT · VTT · ASS · SSA · MicroDVD · SubViewer · TTML · SBV · LRC · SAMI · MPL2 · SCC · EBU STL
- **4 个工具**:格式转换 / 质量校验 / 文本规范化 / 字幕信息
- **体积**:wasm 584KB gz / JS 119KB gz / CSS 8KB gz
- **技术栈**:Rust + wasm-pack + React 19 + TS + Vite 8 + Tailwind v4 + shadcn/ui
- **底层库**:subtitler 2.6.1(<https://crates.io/crates/subtitler>)
- **开源**:<https://github.com/subtitle-rs/subtitle-format-conversion>
